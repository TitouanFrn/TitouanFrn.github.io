Projet Robotique Mobile et Navigation Autonome

Application sur Robot TurtleBot3 (ROS / C++ / Python)

Liens et Ressources Utiles

  • C++ : CPP Reference, CPlusPlus
  • Python : W3Schools
  • ROS : ros.org, Tutoriels ROS, Liste de commandes ROS
  • Messagerie standard : std_msgs, common_msgs, geometry_msgs, sensor_msgs
Mise à jour de l'horloge Raspberry : Exécuter le script horloge.sh.
Rappel environnement : À chaque ouverture de session ou redémarrage du simulateur Gazebo / TB3, exécuter dans un terminal : source init.sh

1. Procédure d'accès au TurtleBot3

  1. Installer l'outil MobaXterm.
  2. Ouvrir une session SSH vers le robot TB3 via l'adresse IP de la carte Raspberry.
  3. Transférer le package du projet dans le dossier catkin_ws/src puis compiler.
  4. Lancer le nœud de communication bas niveau (OpenCR / Raspberry) : roslaunch turtlebot3_bringup turtlebot3_robot.launch
    (Ou via le fichier run_robot.sh présent sur le TB3).

2. Création du Package et Contrôleur ROS

Création du package avec les dépendances requises :

catkin_create_pkg tb3_projet_xx std_msgs geometry_msgs nav_msgs sensor_msgs message_generation actionlib_msgs actionlib tf tf2 tf2_ros rospy roscpp

Création du nœud contrôleur & Topic /log

  • Importation de controleur.cpp dans le dossier src.
  • Création d'un publisher publiant toutes les 2 secondes un message String sur le topic /log.
  • Mise à jour du CMakeLists.txt et compilation du workspace (catkin_make / cm).
  • Création d'un dossier launch/run.launch pour lancer le nœud via roslaunch.

Pilotage du TB3

  • Intégration d'un second publisher pour envoyer des consignes de vitesse (geometry_msgs/Twist).
  • Développement des fonctions avancer(double vitesse), reculer(double vitesse) et arreter() basées sur la période du contrôleur.
  • Gestion de l'arrêt d'urgence et de la coupure propre dans le gestionnaire de signal (sigintHandler lors du CTRL+C).

3. Contrôle et Navigation du TB3

I. Mode Navigation Manuelle

Utilisation de key_input_node.cpp pour piloter le robot au clavier (vitesses linéaires et angulaires paramétrables sans dépasser MAX_LINEAR_SPEED et MAX_ANGULAR_SPEED).

II. Mode Navigation Autonome

II.1 Localisation : Lecture du topic d'odométrie. Conversion des quaternions en angles d'Euler (Yaw) via tf::getYaw() :

#include <tf/tf.h>

II.2 Navigation vers un but :

  • Asservissement en position (linéaire) : Correction proportionnelle PID (gain Kp_pos) avec une tolérance de +/- 0.02m.
  • Asservissement angulaire : Correction PID avec une tolérance de +/- 0.05 rad et utilisation de la fonction cal_delta_Theta pour gérer l'écart angulaire sur [-PI, +PI].
  • Cinématique inverse : Calcul de distance et d'angle cible par atan2() et sqrt() dans un plan cartésien (2D Nav Goal depuis RViz).

4. Perception LIDAR & Obstacles

Exploitation du capteur LIDAR (LDS-01 / LDS-02) publiant sur le topic associé (type sensor_msgs/LaserScan).

  • Division de l'environnement proche en 8 régions égales.
  • Filtrage des valeurs invalides (hors range_min / range_max).
  • Calcul de la distance minimale par région pour détecter la présence d'obstacles.
  • Visualisation dynamique sous RViz à l'aide de marqueurs visualization_msgs/MarkerArray (fichiers rviz_tb3.launch et tb3_lidar.rviz).

5. Actions, Services & SLAM

  • Actions ROS : Utilisation de Move.action, compilation en deux temps, et intégration d'un serveur d'action dans le contrôleur.
  • Services ROS : Définition de pos_service.srv pour collecter dynamiquement des listes de positions cibles stockées dans un vecteur (std::vector<Pose2D>).
  • SLAM (Cartographie) : Lancement du Gmapping (turtlebot3_slam.launch), exploration par téléopération, et sauvegarde de la carte via map_server map_saver (fichiers map.pgm et map.yaml).
  • Planification de trajectoire : Intégration du package AStar-ROS pour une navigation autonome sur grille d'occupation.
