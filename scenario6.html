Scénario 6 — Mesure de température et gestion I²C

Projet Domotique & IoT - ESIEE Paris

Objectif et Description

Ce scénario consiste à intégrer un capteur de température intelligent (TMP102) sur le bus I²C. L'objectif est d'assurer une mesure précise de la température ambiante, et d'automatiser le pilotage de la fenêtre selon plusieurs seuils thermiques (fermeture en cas de froid, ouverture en cas de forte chaleur et zone de confort manuelle intermédiaire).

1. Configuration de l'I²C et choix des paramètres

La communication avec le capteur de température s'appuie sur le bus I²C1 :

  • Broches utilisées : PB8 pour la ligne d'horloge (SCL) et PB9 pour la ligne de données (SDA).
  • Adresse I²C du capteur : Fixée à 0x48 (décalée à 0x90 avec le bit de lecture/écriture dans la bibliothèque HAL).
  • Paramètres du bus : Mode standard à 100 kHz, avec utilisation des résistances de tirage (pull-up) externes indispensables sur le bus.

2. Architecture logicielle : Utilisation de drivers dédiés (tmp102.c / tmp102.h)

Afin de structurer proprement le code et d'éviter d'alourdir le fichier principal main.c, un driver spécifique a été conçu pour le capteur TMP102. Il encapsule l'initialisation, la lecture brute des registres et les conversions de température.

Fichier d'en-tête : tmp102.h

#ifndef TMP102_H
#define TMP102_H

#include "main.h"

#define TMP102_ADDR (0x48 << 1)
#define TMP102_REG_TEMP 0x00
#define TMP102_REG_CONFIG 0x01

Fichier source : tmp102.c

#include "tmp102.h"

extern I2C_HandleTypeDef hi2c1;

HAL_StatusTypeDef TMP102_Init(void)
{
    if (HAL_I2C_IsDeviceReady(&hi2c1, TMP102_ADDR, 2, 100) != HAL_OK)
    {
        return HAL_ERROR;
    }
    uint8_t pData[3] = { TMP102_REG_CONFIG, 0x60, 0xA0 };

    if (HAL_I2C_Master_Transmit(&hi2c1, TMP102_ADDR, pData, 3, 100) != HAL_OK)
    {
        return HAL_ERROR;
    }

    uint8_t reg = TMP102_REG_CONFIG;
    uint8_t lu[2];

    HAL_I2C_Master_Transmit(&hi2c1, TMP102_ADDR, ®, 1, 100);
    HAL_I2C_Master_Receive(&hi2c1, TMP102_ADDR, lu, 2, 100);

    char msg[60];
    sprintf(msg, "Config TMP102 : 0x%02X 0x%02X\r\n", lu[0], lu[1]);
    HAL_UART_Transmit(&huart2, (uint8_t*)msg, strlen(msg), 100);

    return HAL_OK;
}

HAL_StatusTypeDef TMP102_Measure(int16_t *raw_temp)
{
    uint8_t data[2] = {0};
    uint8_t reg = TMP102_REG_TEMP;

    if (HAL_I2C_Master_Transmit(&hi2c1, TMP102_ADDR, ®, 1, 100) != HAL_OK)
    {
        return HAL_ERROR;
    }

    if (HAL_I2C_Master_Receive(&hi2c1, TMP102_ADDR, data, 2, 100) != HAL_OK)
    {
        return HAL_ERROR;
    }

    *raw_temp = (int16_t)((data[0] << 4) | (data[1] >> 4));

    if (*raw_temp & 0x800)
    {
        *raw_temp |= 0xF000;
    }

    return HAL_OK;
}

float TMP102_RawToCelsius(int16_t raw_temp)
{
    return (float)raw_temp * 0.0625f;
}

int32_t TMP102_RawToMilliC(int16_t raw_temp)
{
    return ((int32_t)raw_temp * 1000) / 16;
}

3. Intégration dans la boucle principale et gestion multi-seuils

L'acquisition est réalisée périodiquement (toutes les 200 ms). La température mesurée pilote automatiquement l'état de la fenêtre selon une stratégie à plusieurs seuils :

  • Forte chaleur (> 28°C) : Ouverture automatique de la fenêtre si le système est en mode HOME.
  • Température critique / Froid (≤ 23°C) : Fermeture automatique de la fenêtre pour préserver la chaleur.
  • Zone d'alerte intermédiaire (entre 23°C et 26°C) : Envoi d'un message d'avertissement sur l'UART.
  • Zone de confort libre (entre 26°C et 28°C) : Le contrôle manuel de la fenêtre par bouton reste totalement libre.
uint32_t current_tick_temp = HAL_GetTick();
if (current_tick_temp - last_temp_read >= TEMP_READ_INTERVAL)
{
    last_temp_read = current_tick_temp;
    int16_t raw_temp = 0;
    
    if (TMP102_Measure(&raw_temp) == HAL_OK)
    {
        current_temp = TMP102_RawToCelsius(raw_temp);
        
        if (current_temp > TEMP_HOT_THRESHOLD)
        {
            if (currentMode == MODE_HOME && fenetre_active == 0)
            {
                fenetre_active = 1;
                currentEtat = MODE_OPEN;
                char hot_msg[] = "[INFO] Il fait trop chaud (> 28C) - Fenetre ouverte\r\n";
                HAL_UART_Transmit(&huart2, (uint8_t*)hot_msg, strlen(hot_msg), 100);
            }
        }
        else if (current_temp <= TEMP_CRITICAL_THRESHOLD) 
        {
            if (currentMode == MODE_HOME && fenetre_active == 1)
            {
                fenetre_active = 0;
                currentEtat = MODE_CLOSED;
                char f_msg[] = "[ALERTE] Temperature critique <= 23C - Fenetre fermee\r\n";
                HAL_UART_Transmit(&huart2, (uint8_t*)f_msg, strlen(f_msg), 100);
            }
        }
        else if (current_temp > TEMP_CRITICAL_THRESHOLD && current_temp <= TEMP_WARNING_HIGH) 
        {
            char temp_warn_msg[60];
            sprintf(temp_warn_msg, "[ATTENTION] Temperature fraiche (zone d'alerte) : %.1f C\r\n", current_temp);
            HAL_UART_Transmit(&huart2, (uint8_t*)temp_warn_msg, strlen(temp_warn_msg), 100);
        }

        update_lcd_flag = 1;
        
        char temp_msg[50];
        int32_t mc  = TMP102_RawToMilliC(raw_temp);
        int32_t ent = mc / 1000;
        int32_t dec = (mc < 0 ? -mc : mc) % 1000 / 10;

        sprintf(temp_msg, "Temperature : %s%ld.%02ld C\r\n",
                (mc < 0 && ent == 0) ? "-" : "", ent, dec);
        HAL_UART_Transmit(&huart2, (uint8_t*)temp_msg, strlen(temp_msg), 100);
    }
    else
    {
        char err_msg[] = "[ERREUR] Lecture TMP102 echouee\r\n";
        HAL_UART_Transmit(&huart2, (uint8_t*)err_msg, strlen(err_msg), 100);
    }
}

4. Observation et analyse des trames I²C à l'analyseur logique

L'observation des signaux physiques SCL et SDA à l'aide d'un analyseur logique a permis de valider les différentes phases de la communication I²C :

  • Phase de Start et Adresse : Émission de la condition de START suivie de l'octet d'adresse 0x90 (écriture de l'adresse 0x48 avec le bit R/W à 0), confirmée par un accusé de réception (ACK) émis par le capteur.
  • Pointeur de registre : Envoi de l'octet 0x00 pour pointer sur le registre interne de température.
  • Phase de Restart et Lecture : Émission d'un RESTART suivi de l'octet 0x91 (adresse 0x48 avec R/W à 1), permettant au capteur de retourner les 2 octets de données suivis d'un NACK et d'un STOP.

Difficultés rencontrées et résolutions

  • Absence de réponse I²C (TMP102 absent) :
    Problème : L'exécution renvoyait systématiquement une erreur de non-ack de l'appareil.
    Résolution : Vérification rigoureuse de l'assignation des broches dans STM32CubeMX et validation de la présence des résistances de tirage (pull-up) indispensables sur les lignes du bus I²C.
  • Support des nombres à virgule flottante (float) :
    Problème : L'affichage formaté avec %.1f ou l'utilisation de décimales provoquait des erreurs du linker.
    Résolution : Ajout du drapeau de liaison -u _printf_float dans les propriétés du projet (MCU GCC Linker -> Miscellaneous) pour autoriser le formatage des décimales via sprintf.
  • Organisation du code et modularité :
    Problème : Centraliser toute la logique de bas-niveau et de conversion directement dans le fichier main.c rendait la maintenance complexe.
    Résolution : Création des fichiers dédiés tmp102.c et tmp102.h pour encapsuler proprement les fonctions du capteur, allégeant ainsi considérablement le fichier principal.
