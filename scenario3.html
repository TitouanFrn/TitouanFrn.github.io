Scénario 3 — Détection de gaz et fumées (Capteur MQ-2 et ADC)

Projet Domotique & IoT - ESIEE Paris

Objectif et Description

Ce troisième scénario concerne la surveillance de la qualité de l'air et la détection de situations anormales (gaz ou fumées) à l'aide d'un capteur analogique MQ-2.

  • La sortie analogique du capteur est acquise périodiquement par le convertisseur analogique-numérique (ADC).
  • Constituant une fonction critique de sécurité, cette surveillance reste active en permanence, indépendamment des modes HOME ou AWAY.
  • Lorsque la valeur mesurée dépasse un seuil de déclenchement défini (GAS_THRESHOLD), le système active une LED d'alarme dédiée et un signal sonore via le buzzer de manière non bloquante, tout en prévoyant l'affichage d'un message explicite (« GAS ALERT ») sur l'UART et le LCD.

Schéma fonctionnel de l'acquisition ADC et du capteur de gaz MQ-2

Justification des choix techniques et configuration

1. Acquisition périodique par l'ADC et seuil de déclenchement

L'acquisition de la tension analogique du capteur MQ-2 est effectuée de manière non bloquante toutes les 100 ms grâce à un test temporel basé sur HAL_GetTick(). Suite à la caractérisation expérimentale du capteur dans l'environnement du montage, le seuil de déclenchement de l'alarme a été fixé à 3500 (valeur brute ADC).

La fonction de lecture de l'ADC est implémentée comme suit :

uint32_t Read_MQ2_ADC(void)
{
    uint32_t val = 0;
    HAL_ADC_Start(&hadc1);
    if (HAL_ADC_PollForConversion(&hadc1, 10) == HAL_OK)
    {
        val = HAL_ADC_GetValue(&hadc1);
    }
    HAL_ADC_Stop(&hadc1);
    return val;
}

2. Gestion non bloquante de l'alarme gaz

Afin de ne pas bloquer l'exécution globale du microcontrôleur, la commutation du buzzer et le clignotement de la LED d'alarme sont gérés de façon asynchrone dans la boucle infinie while(1) :

    uint32_t current_tick = HAL_GetTick();
    if (current_tick - last_adc_read >= ADC_READ_INTERVAL)
    {
        last_adc_read = current_tick;
        adc_gas_val = Read_MQ2_ADC();

        if (adc_gas_val > GAS_THRESHOLD)
        {
            gaz_active = 1;
        }
        else
        {
            gaz_active = 0;
        }
    }

    if (alarm_active == 1 || gaz_active == 1)
    {
        uint32_t current_tick_alarm = HAL_GetTick();
        uint32_t current_toggle = HAL_GetTick();

        if (current_toggle - last_buzzer_toggle >= 1)
        {
            last_buzzer_toggle = current_toggle;
            HAL_GPIO_TogglePin(BUZZER_GPIO_Port, BUZZER_Pin);
        }
        if (current_tick_alarm - last_led_toggle >= 250)
        {
            last_led_toggle = current_tick_alarm;
            HAL_GPIO_TogglePin(LED_INTRUSION_GPIO_Port, LED_INTRUSION_Pin);
        }
    }
    else
    {
        HAL_GPIO_WritePin(LED_INTRUSION_GPIO_Port, LED_INTRUSION_Pin, GPIO_PIN_RESET);
        HAL_GPIO_WritePin(BUZZER_GPIO_Port, BUZZER_Pin, GPIO_PIN_RESET);
    }

Difficultés rencontrées et résolution (Calibrage du seuil de gaz)

Une fois le code implémenté et l'ensemble des capteurs câblés, nous avons rencontré des difficultés lors de l'ajustement de la valeur du seuil GAS_THRESHOLD. Suivant les réglages, soit le capteur déclenchait l'alarme en permanence, soit il ne détectait aucune variation.

Pour résoudre ce problème, nous sommes passés en mode de débogage afin d'analyser les valeurs brutes de l'ADC en temps réel. Cela nous a permis d'identifier la valeur de référence à l'air libre d'une part, et la valeur relevée en présence de gaz d'autre part. Cette phase de caractérisation expérimentale nous a ainsi permis d'ajuster précisément le seuil à 3500, garantissant un fonctionnement fiable et stable du système de sécurité.
