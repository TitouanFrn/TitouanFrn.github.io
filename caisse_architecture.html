1. Architecture et base de données

Tables Supabase, isolation par PIN et suppression en cascade.

Objectif

Faire cohabiter plusieurs restaurants dans une seule base de données, sans que l'un voie les commandes ou le menu d'un autre.

Les tables

TableRôle
restaurantsUn restaurant : nom et code PIN à 6 chiffres.
cash_sessionsUne session de caisse (ex. « Service du midi »), ouverte pour un restaurant.
menu_itemsLes plats : nom, prix, catégorie, image ou émoji.
ordersUne commande : ticket, statut, total, session, et infos client/salle si commande à distance.
order_itemsLes lignes d'une commande : plat et quantité.

Toutes les tables de données portent un restaurant_id, qui sert de filtre dans chaque requête.

Isolation par restaurant

Après la connexion par PIN, l'identifiant du restaurant est conservé dans le localStorage du navigateur. Chaque page le relit pour filtrer ses requêtes :

const storedRestaurantId = localStorage.getItem('restaurant_id');

const { data } = await supabase
  .from('orders')
  .select('id, created_at, status, ticket_number')
  .eq('status', 'pending')
  .eq('restaurant_id', storedRestaurantId);

Si aucun identifiant n'est présent, la page renvoie l'utilisateur vers le portail de connexion.

Suppression « en cascade » manuelle

Pour éviter les erreurs de clé étrangère, la suppression est faite à la main, du plus petit élément au plus grand :

  • Un plat : on supprime d'abord ses lignes dans order_items, puis le plat.
  • Une session : on retrouve ses commandes, on supprime leurs order_items, puis les commandes, puis la session.
await supabase.from('order_items').delete().in('order_id', orderIds);
await supabase.from('orders').delete().eq('session_id', sessionId);
await supabase.from('cash_sessions').delete().eq('id', sessionId);

Conventions de code

  • "use client" sur les composants qui utilisent des hooks React ou le localStorage.
  • revalidate = 0 sur les pages serveur critiques, pour toujours afficher des données fraîches.
  • Un composant Header commun à toutes les pages (titre, icône, bouton retour) pour garder une interface cohérente.
