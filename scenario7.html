Scénario 7 — Recomposition architecturale et gestion asynchrone par Timer

Projet Domotique & IoT - ESIEE Paris

Objectif et Description

Ce scénario vise à optimiser l'architecture logicielle globale du système domotique en éliminant l'utilisation de boucles temporelles logicielles basées sur HAL_GetTick() pour l'acquisition des capteurs, ainsi qu'en nettoyant en profondeur les routines d'interruption. L'objectif est de confier le déclenchement des mesures à un Timer matériel (avec une période configurée entre 2 et 5 secondes) et d'externaliser les transmissions UART et l'affichage LCD dans la boucle principale while(1). Ce mécanisme repose sur un système de drapeaux (flags) et d'identifiants de messages, garantissant ainsi un microcontrôleur fluide, réactif et non saturé. De plus, un second bouton a été intégré au montage pour rendre la bascule entre les modes HOME et AWAY plus accessible.

1. Suppression du polling et intégration d'un Timer matériel

L'acquisition périodique des capteurs ne repose plus sur des vérifications temporelles logicielles (polling) dans la boucle principale. Elle est désormais pilotée matériellement par une interruption de Timer (TIM2).

  • Déclencheur matériel : Le Timer génère une interruption périodique (configurée entre 2 et 5 secondes).
  • Cycle d'exécution strict : Timer → acquisition capteurs → traitement → actions → affichage.
  • Variables globales associées : Déclaration de variables de contrôle pour synchroniser les tâches asynchrones.

Variables globales (/* USER CODE BEGIN PV */)

volatile uint8_t timer_acquisition_flag = 0;
volatile uint8_t uart_msg_id = 0;

2. Nettoyage des routines d'interruption (HAL_GPIO_EXTI_Callback)

Pour éviter de saturer le microcontrôleur et de le ralentir, toutes les fonctions bloquantes (comme HAL_UART_Transmit) ont été totalement supprimées des routines d'interruption (boutons et capteurs). Les ISR (Interrupt Service Routines) se contentent désormais de modifier des variables d'état et d'affecter un identifiant de message (uart_msg_id).

Routine d'interruption externe

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
  // Bouton de changement de mode (Bouton 1 ou Bouton 2)
  if (GPIO_Pin == BT_MODE_Pin || GPIO_Pin == BT_MODE2_Pin)
  {
    uint32_t current_time = HAL_GetTick();
    if ((current_time - last_interrupt_time) > 200)
    {
      last_interrupt_time = current_time;

      if (currentMode == MODE_HOME)
      {
        currentMode = MODE_AWAY;
        currentEtat = MODE_CLOSED;
        fenetre_active = 0;
        uart_msg_id = 2;
      }
      else
      {
        currentMode = MODE_HOME;
        alarm_active = 0;
        currentEtat = MODE_CLOSED;
        uart_msg_id = 1;
      }
      update_lcd_flag = 1;
    }
  }
  // Capteur PIR
  else if (GPIO_Pin == PIR_Pin)
  {
    if (currentMode == MODE_AWAY)
    {
      alarm_active = 1;
      uart_msg_id = 3;
      update_lcd_flag = 1;
    }
  }
  // Bouton Fenêtre / Servomoteur
  else if (GPIO_Pin == BT_FENETRE_Pin)
  {
    uint32_t current_time_2 = HAL_GetTick();
    if ((current_time_2 - last_interrupt_time_2) > 500)
    {
      last_interrupt_time_2 = current_time_2;

      if (currentMode == MODE_HOME)
      {
          if (currentEtat == MODE_CLOSED)
          {
              currentEtat = MODE_OPEN;
              fenetre_active = 1;
              uart_msg_id = 4;
          }
          else
          {
              currentEtat = MODE_CLOSED;
              fenetre_active = 0;
              uart_msg_id = 5;
          }
          update_lcd_flag = 1;
      }
      else
      {
          currentEtat = MODE_CLOSED;
          fenetre_active = 0;
      }
    }
  }
}

3. Traitement asynchrone dans la boucle principale (while(1))

La boucle while(1) analyse désormais de manière non bloquante les drapeaux positionnés par les interruptions (EXTI) et le Timer matériel afin d'effectuer les transmissions UART et d'exécuter les acquisitions des capteurs.

Gestion des messages UART asynchrones

4. Intégration du nouveau bouton de mode

Afin de pallier un problème d'accessibilité sur la carte, un second bouton a été mis en place pour gérer le mode HOME/AWAY. Pour ce faire, la broche PC12 a été configurée en mode interruption externe (EXTI).

#define BT_MODE2_Pin GPIO_PIN_12
#define BT_MODE2_Port GPIOC

Comme présenté dans le code des interruptions ci-dessus, la condition utilise l'opérateur logique OU (||) pour accepter indifféremment l'un ou l'autre des boutons.

Difficultés rencontrées et résolutions

  • Saturation et blocage du microcontrôleur dans les interruptions :
    Problème : L'utilisation de fonctions de transmission synchrone de type HAL_UART_Transmit directement à l'intérieur des routines d'interruption allongeait considérablement le temps d'exécution des ISR, créant des risques de perte d'événements.
    Résolution : Suppression totale des appels UART dans les interruptions au profit d'un système d'identifiants de messages (uart_msg_id) traités en différé et de manière non bloquante dans la boucle principale.
  • Rigidité des acquisitions logicielles :
    Problème : Le cadencement des capteurs par des instructions logicielles basées sur le temps écoulé laissait trop de place aux interférences de la boucle principale.
    Résolution : Implémentation d'un cadencement matériel strict via un Timer (TIM2), garantissant une chronologie déterministe.
